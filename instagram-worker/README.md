# Instagram: iPhone как пульт, браузер как исполнитель

Wazzup для этого варианта не нужен. Сотрудник работает в `/discovery/` на iPhone или компьютере: выбирает своего блогера, проверяет текст и разрешает отправку. Сервер CRM фиксирует неизменяемое задание. Отдельный worker открывает Instagram в **обычном браузере с вашей сессией**.

## Что реально делает код

- Заходит на одобренный профиль, открывает сообщение, проверяет единственного адресата в заголовке по нику и ссылке.
- Заполняет утверждённый текст, отмечает границу попытки отправки в CRM, нажимает Send.
- Считает результат подтверждённым по интерфейсу только при появлении новой строки сообщения и очистке поля ввода. Это не подтверждение доставки/прочтения API.
- При входе, challenge/checkpoint, неоднозначной кнопке/адресате — останавливается с защищённым скриншотом. Проверки платформы не обходит.
- После потери ответа/аренды на границе отправки — uncertain, без автоматического повторного сообщения.
- «Обновить чат» получает новый скриншот; сотрудник смотрит его на iPhone и может написать ответ через того же робота. Чужие диалоги массово не читаются, история не выдаётся за структурированные данные API.

Один аккаунт = одна выполняемая задача. Все сотрудники используют общую CRM; задания и скриншоты доступны своему менеджеру и администратору.

## Установка

Нужен отдельный постоянно работающий компьютер/сервер с Chromium, постоянным закрытым каталогом профиля и возможностью один раз открыть видимый браузер (локально или через защищённый удалённый рабочий стол). Обычный статический хостинг для worker не подходит.

```sh
cd instagram-worker
npm ci
# Если Chromium отсутствует: установите его штатным способом или npx playwright install chromium.
# Секреты задаются защищёнными настройками процесса, не аргументами командной строки.
npm run login
npm run account
# Сохраните показанный числовой ID как INSTAGRAM_EXPECTED_ACCOUNT_ID.
npm start
```

Переменные worker: `INSTAGRAM_BROWSER_PROFILE_DIR`, `CHROMIUM_PATH` при необходимости, HTTPS `CRM_ORIGIN`, `BROWSER_ACCOUNT_ID`, `INSTAGRAM_BROWSER_WORKER_SECRET`, `INSTAGRAM_EXPECTED_ACCOUNT_ID`.

На сервере CRM: `DISCOVERY_ENABLED=1`, совпадающие `BROWSER_ACCOUNT_ID` и `INSTAGRAM_BROWSER_WORKER_SECRET`, постоянный `BROWSER_SCREENSHOT_DIR`. `INSTAGRAM_TRANSPORT=browser` отключает прежний Instagram-worker Wazzup. Это не меняет отдельный WhatsApp-процесс видео.

**Вход выполняет человек:** в видимом браузере `npm run login`, затем закрывает окно. Пароль не вводится в CRM, исходники или чат. Сам каталог профиля содержит сессию: хранить с ограниченными правами, не коммитить и не публиковать. На iPhone достаточно открыть HTTPS CRM → «Поделиться» → «На экран Домой».

## Проверка перед вашим Instagram

`npm test` запускает настоящий Chromium **на локальном тестовом чате**, проверяет отправку и отказ при неверном адресате. Это не тест с вашим Instagram-аккаунтом. До включения нужны ручной вход и проверка текущего интерфейса Instagram на тестовом адресате. Если интерфейс отличается, worker остановится; `INSTAGRAM_CHAT_HEADER_SELECTOR` и `INSTAGRAM_MESSAGE_ROW_SELECTOR` настраиваются только после проверки реального экрана, не вслепую.

Данные API worker защищены отдельным секретом; сессия Instagram остаётся только на его машине. Скриншоты лежат вне web root и выдаются через авторизацию CRM. Массовые обходы ограничений, CAPTCHA и скрытая смена аккаунтов не реализованы. Объём работы и частоту нужно согласовать для вашего аккаунта; отсутствие ограничений со стороны Instagram не гарантируется.
