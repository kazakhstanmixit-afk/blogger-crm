# MIXIT Connect: поиск, переписка, интеграции и финансовый реестр

Приложение `/discovery/` работает на iPhone и компьютере с **существующими входами и базой Blogger CRM**. Данные общие. Новые маршруты включаются DISCOVERY_ENABLED=1. Текущие ограничения operator/read-only и старые экраны не заменяются.

## Поиск → менеджер

CSV/JSON Apify → preview → дубли по Instagram и доступному ID аккаунта → существующая bloggers. Из relatedProfiles берутся только реально присутствующие рекомендации, с источником и исходным профилем. История, ответственные, цены и статусы существующих блогеров сохраняются.

Администратор может создать автоматическое задание по ключам, выбрать менеджеров и повтор раз в сутки. Сервер запускает **настроенную задачу Apify**, опрашивает run, загружает dataset, проверяет дубли и распределяет новых кандидатов по текущей загрузке выбранных менеджеров. Для выгрузок видео используются ownerUsername/ownerId, а не ID ролика как ID аккаунта.

Нужны APIFY_TOKEN, APIFY_SEARCH_TASK_ID и APIFY_QUERY_FIELD: реальное поле поиска выбранной задачи. Дополнительно APIFY_SEARCH_BASE_INPUT_JSON, APIFY_QUERY_IS_ARRAY=1, APIFY_SEARCH_BUDGET_LIMIT_USD (по умолчанию 2 USD). DISCOVERY_SEARCH_ENABLED=1 включает worker. Цена и поддержка maxTotalChargeUsd зависят от модели оплаты выбранного Actor; лимит не заменяет контроль расходов аккаунта. Задача настраивается под реально используемый Actor, универсальная схема его input не выдумывается. Потерянный ответ запуска отмечается uncertain и не запускает второй платный run.

## iPhone → отдельный браузер Instagram → результат

По уточнению пользователя Wazzup для Instagram заменён браузерным исполнителем. iPhone — пульт общего приложения CRM. Сотрудник выбирает блогера и проверяет текст; CRM фиксирует одобренные ник/сообщение; отдельный браузер с вашей сессией выполняет отправку. При запросе входа или неоднозначном адресате — остановка. Скриншоты доступны только своему менеджеру/администратору. Через них можно обновить чат и подготовить ответ. Доставка/прочтение не объявляются подтверждёнными по одному скриншоту.

Исходники и точный запуск — [instagram-worker/README.md](../instagram-worker/README.md). Вход в Instagram ручной на машине worker, пароль не хранится в CRM. Это отдельный постоянно работающий процесс, не скрытое управление приложением Instagram на iPhone.

Прежний необязательный Instagram-транспорт Wazzup не используется приложением и не запускается без явного INSTAGRAM_TRANSPORT=wazzup. Отдельный WhatsApp-процесс видео остаётся в Barter Box.

«Подготовить сообщение» при настроенном Gemini использует только доступные данные профиля; иначе показывает обозначенный шаблон. Сотрудник проверяет текст до отправки.

## CRM → Barter Box

Кнопка «Интеграция → Barter Box» передаёт профиль по серверной связи; URL содержит только стабильный ID CRM. В существующей компьютерной форме подставляются имя, профиль и контакт. Поля товара/даты/условий подтверждает менеджер. Несколько месяцев используют тот же CRM ID, а интеграции остаются отдельными.

Нужны BARTER_BOX_ORIGIN, FLOW_CRM_SECRET и FLOW_EMPLOYEE_MAP_JSON (точное соответствие ID пользователей CRM именам Barter Box). Если сопоставление сотрудника не настроено, форма требует указать ответственного, не приписывает действие автоматически Нине. Смена Instagram у связанного ID или конфликт профиля требует ручной сверки.

## Оплата

При FINANCE_BRIDGE_ENABLED=1 POST `/api/integrations/payments` создаёт запись **в существующей payments**, а не второй финансовый интерфейс. Проверяются ID блогера/ответственного, сумма, этап и связанные видео; повтор не создаёт вторую запись. Одна сумма может относиться к нескольким роликам. ИП без проверенного счёта не передаётся в Bitrix. Загрузка счёта в старой таблице CRM и точная настройка вебхука описаны в [bitrix-payments.md](bitrix-payments.md). Денежная выплата этим кодом не выполняется.

Barter Box опрашивает только созданную связанную запись и получает факт статуса и уже загруженные существующим механизмом чеки. Никакой автоматической отметки «оплачено» по заявке или закрытию внешней задачи.

**Требуется для реального включения:** конкретный webhook и схема вкладки Bitrix «Согласование оплаты», а для юридической генерации — утверждённые шаблоны договора/счёта/АВР. Обработчик Bitrix написан, но его реальное подключение не проверено. Универсальные задачи вместо финансового процесса и придуманные юридические документы не создаются.

## Проверка и включение

`cd server && npm ci && node --test test/*.test.js`.

Тесты проверяют реальный Express router, изменение существующих записей, очередь отправки с фиктивным транспортом, входящие/статусы, uncertain без повторов, автопоиск, расходы и финансовые связи. Нет обращений к реальным блогерам, платных runs и prod-данным. Для iPhone: один HTTPS-адрес CRM → Safari → «Поделиться» → «На экран Домой». Проверка на физическом iPhone ещё не выполнялась.

Сначала резервная копия db.json и тестовая среда. Новые секреты задаются только защищёнными настройками сервера. Старые Supabase-зеркала и существующий реестр оплат не переписываются.
