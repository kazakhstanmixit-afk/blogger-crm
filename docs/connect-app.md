# MIXIT Connect: приложение, уведомления и первые контакты

## Пользовательский цикл

Один HTTPS-адрес существующей CRM: `/discovery/`. У менеджера и тимлида существующие учётные записи. Данные на телефоне и компьютере общие.

1. **Блогеры.** Фильтры «Новые», «Подготовить контакт», «Ждём ответ», «Ответили», «Позже». Менеджер берёт кандидата и готовит стандартное первое обращение о бартере. Текст можно проверить до отправки. Первичный контакт повторно не ставится для уже контактированного блогера; продолжение — через диалог.
2. **Готовые обращения.** Менеджер ставит проверенный текст в очередь браузерного робота. Отправка выполняется только подключённым Windows-роботом. `sent_ui` означает появление в интерфейсе Instagram, не прочтение. Отправленные обращения не показывают кнопку повторной отправки.
3. **Переписка.** Сообщения сгруппированы по блогерам; диалог открывается с историей и полем ответа. Есть фиксация прайса, объёма размещения, WhatsApp, города и исходного ответа. Фиксация прайса не означает согласие компании оплатить его.
4. **Условия / согласование.** Точный текст, товар, себестоимость, доплата, расходы и исходные условия. Фильтры решений. Тимлид одобряет, отклоняет либо просит исправить; собственное предложение согласовать нельзя. Менеджер после одобрения создаёт обращение с одобренным текстом. Решение не выполняет платёж и не запускает отправку само по себе.
5. **Уведомления.** Ответ блогера → текущему менеджеру; ожидающее предложение → согласующим; решение → менеджеру; сбой/вход Instagram → ответственному. События можно открыть и отметить прочитанными. События по чужому переданному блогеру прежнему менеджеру не показываются. При первоначальном включении история доступна внутри приложения без массовых push.

## iPhone

Safari → открыть HTTPS `/discovery/` → «Поделиться» → «На экран Домой». Открыть установленное приложение и войти. На iOS 16.4+ перейти «Уведомления» → «Включить уведомления» → разрешить. На компьютере поддерживается Web Push совместимого браузера. Push не зависит от открытой вкладки, но для получения новых событий из Instagram сам робот должен работать.

На экране блокировки только тип события, без текста переписки, телефона, суммы и себестоимости. Нажатие открывает нужный раздел. Доставка push зависит от браузера, разрешений, сети и настроек фокуса устройства. На физическом iPhone в этой разработке пока не проверено.

Кнопка «Отключить на устройстве» удаляет серверную подписку и отписывает браузер. Выход из приложения также пытается отключить подписку. Первые сообщения по умолчанию шаблонные; Gemini для них не требуется. `DISCOVERY_FIRST_CONTACT_TEMPLATE` позволяет задать утверждённый текст с `{manager}` / `{name}`. Генерация Gemini включается отдельно через `DISCOVERY_COMPOSE_MODE=ai` и действующие настройки модели.

## Настройки запуска

Сохранить действующую базу, JWT_SECRET и существующие настройки. Установить серверные зависимости из lock-файла (`npm ci` в `server`) и выполнить обычную сборку/деплой существующей CRM.

```dotenv
DISCOVERY_ENABLED=1
NEGOTIATION_APPROVER_IDS=ID_СОГЛАСУЮЩИХ_ЧЕРЕЗ_ЗАПЯТУЮ
CONNECT_PUSH_ENABLED=1
PUSH_VAPID_SUBJECT=mailto:РЕАЛЬНАЯ-ПОЧТА-АДМИНИСТРАТОРА
PUSH_VAPID_PUBLIC_KEY=ПУБЛИЧНЫЙ-КЛЮЧ
PUSH_VAPID_PRIVATE_KEY=ПРИВАТНЫЙ-КЛЮЧ
```

Сгенерировать пару один раз в защищённом терминале: `node tools/generate-push-keys.cjs`. Вывод сохранить только в защищённых переменных Render; не пересылать в чат и не добавлять в GitHub. Пару сохранять между деплоями. Используется стандарт Web Push, отдельный платный сервис уведомлений не требуется. Сервер отправляет push только при включении и наличии всех настроек. HTTPS и исходящие соединения к push-службам обязательны.

Используются новые технические разделы существующего файла lowdb: `connect_notifications.events`, `connect_notifications.subscriptions`. Отдельная база/платный pilot не создаются. Service worker не кэширует CRM-ответы или учётные данные. Настройки Windows-робота и каталога описаны в `launch-ru.md`.

## Проверка после выкладки

1. Менеджер и другой тимлид входят с разными учётками. Проверить обычную CRM и `/discovery/`.
2. Поставить одно первичное сообщение согласованному тестовому получателю. Убедиться в правильном адресате и точном тексте. Попытка повторного первого контакта не должна создавать новую отправку.
3. После проверенного чтения реального чата получить ответ: он виден в диалоге и создаёт событие менеджеру. Записать прайс/WhatsApp без согласования оплаты.
4. Создать предложение. Тимлид видит событие и может принять решение; менеджер собственное предложение не согласовывает. После решения событие приходит менеджеру.
5. На iPhone установить приложение, подключить push. Создать новое событие при закрытом приложении. Проверить получение и переход из уведомления. Это обязательная реальная проверка, тесты на Chromium её не заменяют.
6. Переназначить тестового блогера: прежнему менеджеру не отправляется новая информация. Проверить отключение push.

## Граница этого изменения

Этот пакет сосредоточен на приложении и уведомлениях. Он не превращает тестовый DOM-адаптер Instagram в гарантированно работающий: реальный вход, селекторы, автор и ID сообщения ещё должны быть подтверждены на аккаунте. Самостоятельные переговоры, обработка неизвестных запросов Direct, медиа и полный цикл WhatsApp не заявляются готовыми. Bitrix/оплаты этим изменением не включаются; прежнее правило «только ИП с проверенным счётом» сохраняется.

### Рассмотрение блогера до подбора товаров

Добавлен отдельный шаг «Передать тимлиду» после фиксации исходного ответа. Карточка сохраняет снимок прайса, условий и профиля; повторное нажатие не создаёт вторую ожидающую заявку. Тимлид может одобрить блогера, отклонить или запросить уточнения. Менеджер получает событие решения. Это не платёжное согласование и не обещание доплаты: товары и конкретное коммерческое предложение согласуются следующим шагом. Технические записи — `contact_reviews` в той же базе CRM.


## Область PR №4

Только приложение `/discovery/`, его первичные контакты, рассмотрение блогеров, согласования и уведомления. Актуальные изменения основной ветки сохраняются. Отличий от main в `client/`, `server/apify-scout.js`, финансовых модулях и `integration-handoff/` быть не должно. В общем `server/index.js` добавлены только подключения двух модулей приложения; в зависимостях — Web Push. Базы и настройки рабочего сервиса этим PR не заменяются. Не применять старые патчи и не деплоить старую копию репозитория вместо слияния PR с текущей main.
