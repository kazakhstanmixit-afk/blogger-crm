## Что включено

- Компактный поиск/подбор товаров в основной компьютерной форме и серверный расчёт себестоимости.
- Отдельная заявка, Сая, склады Алматы/Астана и произвольные сборщики; одна посылка для нескольких видео; обновление связанных интеграций по подтверждённой доставке.
- Постоянная связь профиля CRM с предзаполненной формой интеграции.
- Реальная очередь запросов ТЗ **в существующий Blogery Audit**, получение утверждённой версии и подписанных DOCX/PDF.
- Отправка PDF блогеру через Wazzup; опциональное предварительное разрешение менеджера на автоотправку; статус только по событию канала.
- Версии входящих видео, очередь при неоднозначности и экран выбора нужной интеграции.
- Передача видео + GATE тимлиду двумя связанными сообщениями и разбор его quoted reply по точной версии.
- Задача монтажёру, самостоятельная загрузка файла, защищённое хранение и повторный GATE.
- Сводки логистике в 12:00/15:00 Астана, без дублей и без персональных данных блогера.
- Одна заявка на оплату нескольких видео в существующую CRM; возврат реального статуса и чеков.
- Возврат подтверждённой публикации и доступных метрик в существующее ТЗ Blogery Audit.

Если основной код изменился, сначала проверка и разбор конфликтов. Нельзя заменять рабочие state.json, журнал и index.html вслепую. Патч проверяется на отдельном checkout указанной базы.

## Проверки и реальные ограничения

В Barter Box 29 тестов, в CRM 24, в Blogery Audit 8: всего **61**, включая SQL-путь на тестовом PostgreSQL WASM, генерацию настоящих DOCX/PDF, фиктивные транспортные вызовы, повторы и статусы. Дополнительно сквозной HTTP-сценарий реального Express с синтетическими данными: auth → подбор → общая посылка → сборка → передача → доставка → обратная смена статуса. Синтаксис inline scripts проверен. Физический iPhone и реальные внешние каналы ещё не проверены.

Код конфигурируется, но сам по себе не подключает рабочий Render, Supabase и аккаунты мессенджеров. Внешние отправки, платные поисковые runs, выплаты, миграции prod и продакшен-развёртывание не выполнялись. Точное состояние флагов/ключей перечислено в docs/automation-pilot.md и docs/runtime-configuration.env.example после применения.

Нет конкретного webhook/схемы Bitrix «Согласование оплаты» и утверждённых договорных шаблонов. Эта часть не считается завершённой. Не создаются обычные задачи вместо согласования и не генерируются юридические условия от имени ИП.

Патч не содержит реальных себестоимостей, контактов, банковских данных или загруженных Excel. Каталог готовится tools/prepare_catalog.py и импортируется в закрытое серверное хранилище.
